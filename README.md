# 夜じたて

『月蝕綺譚 -Luna Occulta-』の札絵を、その端末の画面寸法に合わせて**額装**し、
写真に保存するまでを受け持つ道具。

**寸法に合わせて仕立てるから『夜じたて』。**（2026-08-30 に『御霊かざり』から改題）

**壁紙集ではありません。** 公式の絵をそのまま配ることはせず、
選んだ一枚をその場で額装した結果だけを渡します。

---

## これは何をするか

画面の真ん中に**額**、左に**顔の列**、右に**顕れの深さの階梯**。開いた姿はこれひとつで、畳むところはありません。

1. 左の列から御霊を選ぶ（33柱・里の順に縦に並んでいます。名前で探すときは下の名札を押すと一覧が開きます）
2. 右の階梯を**縦になぞって**10段から選ぶ（下が01・上が10。浅いほど暗く静か、深いほど極彩色）
3. その端末の実寸（`screen.width × devicePixelRatio`）に合わせて額装する
4. 写真に保存する

**額は常に全部見えます**（何かに覆われることはありません）。
壁紙にする手順・この端末で通ったことは、左上の **≡** にまとめてあります。

**壁紙に設定するのは、この道具の外です。** ブラウザから壁紙を書き換える手段は
iOS にも Android にも無いため、最後の一手は端末の標準操作に渡します。

### 壁紙にするとき、ひとつだけ

**iOSは既定で顔まで拡大します。**その正体は「**被写体を切り取る**」という設定です。

- 写真アプリから入れる場合は、設定画面で**指2本を近づけて縮める**（上に藍色の帯が出るまで）
- ショートカットを2手だけ組めば、**その設定を切れる**ので縮める操作が要りません
  → **[docs/SHORTCUT.md](docs/SHORTCUT.md)**

## 額装でしていること

2:3 の札絵（1024×1536）は、9:19.5 の画面には入りません。
幅を合わせれば画面の約31%が空き、高さを合わせれば左右の約31%を切り落とすことになります。
そこで:

- 地は**宵闇藍の二色一組**（`#131320` / `#1B1B2E`）。純黒は使わず、二色を統合もしない
- 絵は幅合わせで下寄せに置き、**上端と下端を地へ溶かす**。額縁は描かない（闇から顕れている形にする）
- 溶かし方は「地の色で塗って隠す」のではなく「**絵のほうを削る**」
  （`destination-out`）。塗ると地のグラデーションと色が合わず、境目に線が残る
- **蝕環**をひとつだけ、**絵の後ろに**薄く置く。散らさない。
  釦の帯に届く手前で金泥そのものを溶かして消すので、帯には一切乗らない
- 顔が**時計の帯（上17%）と釦の帯（下12%）を避ける**ように配置する
- 書き出しは **JPEG 品質0.92**（PNG比で約7分の1。自作の地に縞は出ない。第2便で測って決めた）

## 素材

**原本は1枚も入っていません。**
素材蔵（`https://kura.vibe.co.jp/`）が `Access-Control-Allow-Origin: *` を返すため、
ブラウザが直接読み込み、canvas 上で額装しています。

置いてあるのは `ogp.jpg` の1枚だけで、それも**この道具が出した額装済みの絵**を組んだもの
（`scripts/build-ogp.js` が焼く）。SNSに貼ったときの見出し画像として要るためです。

| 出どころ | 使っているもの |
|---|---|
| 公式配布（素材蔵 `kura.vibe.co.jp`） | 札絵 330枚（33柱 × 深さ01〜10）。実行時に読み込み、canvas に載せる |
| 公式配布（`vibe.co.jp/luna-occulta/media/`） | 顔アイコン 29枚。選ぶ札に `<img>` で並べるだけ（canvas には載せない）。顔アイコンがまだ出ていない4柱（トバリ・ゴコウ・マミ・サスラ）は、開いた端末の中で札絵から顔を切り出して並べる（切った絵はどこにも置かない） |
| 自作 | 額装の合成処理・画面・配色の当て方 |

### 札絵のURLは組み立てられない

素材蔵の札絵は径路が4系統に分かれ（`/fuda/` 80枚・`/fuda/v2/` 190枚・`/fuda/v3/` 10枚・`/fuda/app/` 10枚）、
さらにファイル名にも `_v2` `_v3` の変種があります。**同じ御霊の10枚のなかで型が混ざる柱もあります**
（アウン・カルラ・ナルカ・おえん・オロチ・呂屯）。

そのため URL は組み立てず、公式MCP `kitan-lore` の `list_assets(kind=fuda)` から写した台帳
（`scripts/fuda-ledger.json`）の値をそのまま使います。台帳から `index.html` へ焼く手順は下記。

顔アイコンだけは別ホスト（`vibe.co.jp`）にあり、こちらは `Access-Control-Allow-Origin` を返しません。
**選ぶ札に並べるだけなら CORS は要らない**ので `<img>` で表示しています。canvas には載せません。

## 開発

単一の `index.html`。ビルドはありません。名簿だけは台帳から焼きます。

```
node scripts/build-roster.js            # 台帳 → index.html の ROSTER 区画
node scripts/build-roster.js --check    # 焼き直さず、食い違いだけ見る

NODE_PATH=../shikifuda-kasane/node_modules node scripts/check-layout.js
                                        # 画面の実測（押し所・文字・4系統の読み込み・連打）
NODE_PATH=../shikifuda-kasane/node_modules node scripts/check-frame.js [比較用HTML]
                                        # 額装の実測（継ぎ目・蝕環の絵の具・書き出しの重さ）
SPIRIT=orochi DEPTH=9 NODE_PATH=... node scripts/check-frame.js
                                        # 測る一枚を変える

NODE_PATH=../shikifuda-kasane/node_modules node scripts/daily.js [YYYY-MM-DD] [出力先]
                                        # 今日の一枚を焼く（日付を渡せば任意の日を再現できる）
NODE_PATH=../shikifuda-kasane/node_modules node scripts/build-ogp.js
                                        # ogp.jpg を焼く（明朝体がmacOS依存なのでCIでは焼かない）
```

`scripts/` の中身:

| ファイル | 中身 |
|---|---|
| `fuda-ledger.json` | 素材蔵の札絵330枚の台帳（MCP `list_assets` の写し）。**手で編まない** |
| `spirits-table.json` | 札絵を持つ33柱の表（MCP `list_spirits` の写し） |
| `build-roster.js` | 上の2つを `index.html` へ焼く。台帳と表の食い違いはここで落ちる |
| `check-layout.js` | ヘッドレスChromeで画面を実測する |
| `check-frame.js` | 書き出される一枚の中身を実測する。継ぎ目は目で見ず、**行ごとの平均輝度の跳ね**で判定する |
| `daily.js` | 今日の一枚を3寸法ぶん焼く。日付から一意に決める（`.github/workflows/daily.yml` が毎朝呼ぶ） |
| `daily-notes.js` | Release のお品書きを組む。文面をYAMLに埋めない（引用符と改行がシェルで壊れるため） |
| `build-ogp.js` | `ogp.jpg`（2400×1200）を焼く。**宣伝用に別の絵を描かず、この道具が実際に出す絵を並べる** |

### デバッグハッシュ

- `#daily` … ≡ の札に「毎朝ひとりでに替えるなら」（固定URLとコピー釦）を出す。2026-09-03 から案内から外した機能（試験運用中）。仕組みは `docs/SHORTCUT.md` 乙

| ハッシュ | 効果 |
|---|---|
| `#size=1179x2556` | 端末の実寸を上書きする（他機種の見え方を手元で確かめる。ヘッドレスChromeは幅500px未満に縮まないため、これが無いとスマホの縦横比を再現できない） |

### 実機で確かめること

`navigator.share` は **HTTPS でしか動きません**。ローカルサーバーを LAN 経由で開いても通らず、
Artifact プレビューの枠内でも（ページ側が始める保存が塞がれるため）本当の結果になりません。
**GitHub Pages に載せた状態で確かめてください。**
